
## 8. 단계별 워크플로우

### 8-1. 공통 처리 파이프라인 (FR-05~12)

```mermaid
flowchart LR
    A["fetch"] --> B["① 세션확인<br/>401"] --> C["② 형식검증<br/>422"] --> D["③ 데이터검증<br/>404/409"] --> E["④ 처리+커밋"] --> F["⑤ JSON응답"]

    style B fill:#FBE1E1,stroke:#C0392B
    style C fill:#FBE1E1,stroke:#C0392B
    style D fill:#FCEFE3,stroke:#D8964C
    style F fill:#E4F5E9,stroke:#2E8B57
```

①은 인증 필수 API에만, ③은 본문 있는 요청(POST/PATCH)에만 적용. 어느 단계든 실패 시 이후 단계 미실행, 즉시 오류 응답(500 미발생의 구조적 근거).

### 8-2. 시퀀스 — 회원가입

```mermaid
sequenceDiagram
    autonumber
    actor U as 사용자
    participant R as 라우터
    participant C as crud.create_user
    participant DB as PostgreSQL

    U->>R: POST /auth/signup
    R->>DB: SELECT WHERE username=? (중복 확인)
    alt 이미 존재
        DB-->>R: 존재함
        R-->>U: 409
    else 사용 가능
        R->>C: create_user(data)
        C->>DB: INSERT user
        C->>DB: INSERT category ×3
        C->>DB: COMMIT
        DB-->>C: 완료
        C-->>R: User 객체
        R-->>U: 201 Created
    end
```

### 8-4. 시퀀스 — 카테고리 삭제(대표 엣지 케이스)

```mermaid
flowchart TD
    A["DELETE /categories/id"] --> B{"① 세션 확인"}
    B -- "No" --> R1["401"]
    B -- "Yes" --> C{"② 내 카테고리?"}
    C -- "No" --> R2["404"]
    C -- "Yes" --> D{"③ count_contacts<br/>_in_category() 확인"}
    D -- "1건 이상" --> R3["409<br/>'N건 있어 삭제 불가,<br/>종류 먼저 변경'"]
    D -- "0건" --> E["④ DELETE+COMMIT"]
    E --> R4["204"]

    style R1 fill:#FBE1E1,stroke:#C0392B
    style R2 fill:#FBE1E1,stroke:#C0392B
    style R3 fill:#FCEFE3,stroke:#D8964C
    style R4 fill:#E4F5E9,stroke:#2E8B57
```

DB의 FK(RESTRICT)가 최종 안전망이나, 애플리케이션에서 선제적으로 count 확인 후 친절한 409로 응답하는 것이 핵심 요구(PR-09)다. FK 위반을 그대로 노출하면 500이 되어 원인 전달이 불가능하다.
