
## 13. 화면(UI) 설계 상세 — 프론트엔드 구현용

본 장은 02(화면정의서) SCR-002·SCR-003·SCR-900을 TRD 관점에서 재구성한 프론트엔드 구현 명세다.

### 13-1. SCR-002 관리 화면 레이아웃 요약

- 상단: 서비스명, 사용자명, [로그아웃]
- 좌측: 연락처 추가 폼(이름/전화/주소/종류 드롭다운) + [추가]/[취소], 검색창 + [검색/전체], 연락처 목록(총건수 표시)
- 우측: 카테고리 관리(SCR-003) — 목록, [수정]/[삭제], 새 카테고리 입력+[추가]
- 하단: SCR-900 공통 메시지 영역

> ⚠️ **좌측 폼에 [취소] 버튼 추가 (신규)**: 02(화면정의서) v1.1에서 편집모드 이탈 경로 누락이 발견되어 [취소] 버튼이 신규 추가되었습니다. TRD의 레이아웃 설명에도 동일하게 반영합니다.

### 13-2. 연락처 영역 — 구성 요소/동작

| 요소 | 동작 | 호출 API | 성공 시 반응 |
|---|---|---|---|
| 추가 폼+[추가] | 4항목 입력 후 클릭 | POST /contacts | 폼 초기화+목록 재조회 |
| 종류 드롭다운 | 목록 선택 | (GET /categories로 사전 채움) | — |
| 검색창+[검색] | 이름 입력 후 클릭 | GET /contacts?name= (부분일치) | 목록 교체, 총건수 갱신 |
| [전체] | 클릭 | GET /contacts | 전체 목록 복귀 |
| 행의 [수정] | 클릭 | (호출 없음) | 폼에 값 채움+편집모드([추가]→[저장], [취소] 노출) |
| 편집모드 [저장] | 클릭 | PATCH /contacts/{id} | 편집모드 해제+재조회 |
| **편집모드 [취소] (신규)** | 클릭 | (호출 없음) | 폼 초기화+편집모드 해제 |
| 행의 [삭제] | 클릭→confirm | DELETE /contacts/{id} | 재조회 |
| [로그아웃] | 클릭 | POST /auth/logout | SCR-001 전환 |

카테고리를 드롭다운(select)으로 강제하는 이유: 애초에 목록에 있는 값만 선택 가능하게 하는 UI 제약 설계다. 단, API 직접 호출 경로가 있으므로 서버 측 `category_id` 검증은 유지한다(§7).

### 13-3. SCR-003 카테고리 영역

| 요소 | 동작 | 호출 API | 성공 | 실패 |
|---|---|---|---|---|
| 새 카테고리+[추가] | 입력 후 클릭 | POST /categories | 목록+드롭다운 갱신 | 409 이름 중복 |
| 항목 [수정] | 클릭→prompt | PATCH /categories/{id} | 목록+드롭다운+연락처 목록 갱신 | 409 이름 중복(자기 자신 제외) |
| 항목 [삭제] | 클릭→confirm | DELETE /categories/{id} | 목록+드롭다운 갱신 | 409 사용 중(건수 안내) |

### 13-4. SCR-900 공통 메시지/오류 표시 규칙

| 상황 | 화면 동작 |
|---|---|
| 401(로그인 시도 자체 제외) | 세션 만료로 간주 → 로그인 섹션 전환 |
| 404/409/422 | `detail`을 그대로 표시(문구 재생성 없음) |
| 성공(200/201/204) | 안내 1~2초 노출 후 소멸 |
| 422 detail이 배열 | 첫 항목 `msg`만 표시 — 형태는 02 문서 §4-SCR-900 참조 |
