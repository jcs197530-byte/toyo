## 6. 영속화 설계

### 6-1. pickle 대비 전환 전략

| 구분 | 1차(pickle) | 2차(PostgreSQL) |
|---|---|---|
| 저장 시점 | 종료 시 1회 | 요청마다 즉시 커밋 |
| 비정상 종료 | 마지막 저장 이후 소실 | 커밋된 데이터 안전 |
| 동시 사용 | 불가 | 다중 사용자 동시 처리 |
| 부분 수정 | 전체 재저장 | 해당 행만 UPDATE |
| 로그인 상태 | 개념 없음 | sessions도 커밋되어 재시작 후 유지 |

### 6-2. 트랜잭션 예시 — 회원가입

```python
def create_user(db: Session, data: schemas.SignupIn) -> models.User:
    hashed = hash_password(data.password)
    user = models.User(username=data.username, password_hash=hashed)
    db.add(user)
    db.flush()  # user.id 확보(commit 아님)
    for name in ("가족", "친구", "기타"):
        db.add(models.Category(user_id=user.id, name=name))
    db.commit()  # 사용자+카테고리 3개, 전부 성공 또는 전부 실패
    db.refresh(user)
    return user
```

### 6-3. 커밋/롤백 원칙

| 원칙 | 설명 |
|---|---|
| 요청 단위 트랜잭션 | 성공 시 commit, 예외 시 자동 rollback |
| get_db()의 역할 | 요청마다 세션 개설, 종료 시(성공/실패 무관) 반드시 close |
| 부분 실패 방지 | 연관 INSERT는 commit 전 flush로 중간 상태 확인, 최종 commit은 1회 |
| FK 위반 처리 | IntegrityError를 라우터가 포착해 409로 변환 |
